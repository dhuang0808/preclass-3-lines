# 官方要求核实（2026-10-22，北京时间）

来源：[活动主页](https://dev.to/challenges/hacktoberfest-week3-2026-10-19)、[本周规则](https://dev.to/page/hacktoberfest-week3-2026-10-19-contest-rules)、[通用规则](https://dev.to/page/official-hackathon-rules)、[AI 披露](https://dev.to/llms.txt)。模板已从主页链接的预填内容核对。

- 截止：2026-10-25 23:59 PDT，即北京时间 2026-10-26 14:59。
- 本周每人只计第一篇投稿；一个项目可申报多个真正用到的合作技术类别，但每周最多获一个奖。
- 使用主页模板，必带 devchallenge、hf26challenge；说明节省什么劳动、实现方式、开放 AI 的核心作用及开放创新的意义。
- 附代码仓库与部署链接或演示视频；截图占位不能代替演示。获奖文章需英文，中文只具备完成徽章资格。
- 项目和仓库都要在比赛窗口内开始并完成；截止后的代码改动须在 README 标注。参与者需满足官方成年与其他资格条件，待本人核实。
- SerpApi 要在项目中实质提供实时搜索/新鲜资料，在文章奖项部分列明对应类别。
- TabPFN 要从历史表格数据预测、分类或发现异常。官网推荐 3.5 和更完整的预测 agent，没有写必须用最新版。
- Gemma 本地推理是 B 的真实组成部分；是否同时申报该类别由指挥官决定。
- AI 可用且须如实披露：人主写并实质修改可选 some_ai；主要由 agent 生成的文章（即使人批准）用 fully_autonomous；不能标 no_ai 或不披露。Agent 会话/DevRelay 展示可选，只公开脱敏材料。
- 评审顺序：文章质量最重要，其次主题、创意、技术；合作类别另看技术使用。

模板栏目：What I Built / Demo / Code / How I Built It / Why Does Open Innovation Matter? / My Agent Session / The Lazy Payoff / Prize Categories

## 留给指挥官裁决的冲突

1. 不能把 A、B 当作本周两篇独立有效投稿。继续开发 B 主项目、A 备选，不替指挥官决定最终投稿组合。
2. 官网推荐需要签非商业许可的 TabPFN-3.5；任务书指定避免授权的旧版路线。本次仍显式尝试 v2，本地 CPU；不擅自改用 3.5。

## 初始缺项

真实搜索与稳定性证据、成品 README、演示视频/部署链接、英文稿、最终奖项选择、如实的 AI 披露与本人资格核实。A 已有账单文件，但先前质量报告未确认完整记账区间；数据缺口不能直接证明为零消费。
